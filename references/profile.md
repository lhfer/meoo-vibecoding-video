# 宣发版（launch）：让同行想试一试

观众是同行和潜在用户，默认怀疑"又一个 demo 视频"。本 profile 的 brief 默认：`preset product`、更沉稳清晰的声线、7.4 字/秒、气口 ≤ 2.5 s（仅证据段）、block 字幕、轻节奏床 BGM（调性随产品卡）。

## 结构骨架

痛点（作者的真实场景，一句话）→ 我做了什么（一句话，说清替谁解决哪一件事）→ **真实录屏先行（前 10 秒内出现）** → 怎么做的（prompt／agent 对话、关键取舍、花了多久）→ 适合谁／不适合谁 → 诚实边界（版本号、限制、还没做的部分）→ CTA（试用／反馈／关注）。

xs/s 档常见：hook（录屏里最能证明能力的 5 秒）→ 我做了什么 → 怎么做的 → 边界 → CTA。

## 口播 register

- 像跟同行讲自己做的东西：说版本号、限制、未做的部分；把"为什么这么做"讲清楚。
- 不喊、不排比、不"重新定义"、不"震撼／王炸／炸裂／家人们／绝了／秒杀"（本包额外禁词，加在 `banned-words.txt` 之上）。
- 能力主张必须有证据句紧随其后："它能自动归档——你看，这 3 封邮件 2 秒进了对应文件夹。"
- 数字要给条件："100 条测试里 92 条正确，样本是我自己的邮箱。"
- 情绪标签：开头 `[calm]`、demo `[confident]`、边界 `[sincere]`、CTA `[soft]`。

参考口吻（评测夹具 `evals/files/tool.md`）："我做了一个本地资料索引工具，起因是收藏夹越来越大……这个版本还需要手动整理；没有发布用户增长或商业收入数据。"

## 让同行看完（每段至少一种，全片 ≥ 3 种）

| 手法 | 做法 | ✗ / ✓ |
|---|---|---|
| 真实场景 | 痛点用作者自己的一个时刻讲 | ✗ "邮件管理很麻烦" · ✓ "周一早上 200 封未读，我先花 40 分钟归档" |
| 先看结果 | 前 10 秒先放录屏里最能证明能力的 5 秒，再讲怎么做的 | ✓ "你看，这 3 封邮件 2 秒进了对应文件夹" |
| 取舍与失败 | 讲一个做错了又改的决定，比讲成功可信 | ✓ "第一版只用规则，100 封里错了 30 封；换成规则 + AI 判断才到 92" |
| 数字给条件 | 每个数字带样本与条件 | ✗ "准确率 92%" · ✓ "100 条测试里 92 条正确，样本是我自己的邮箱" |
| 边界坦白 | 主动说不适合谁、没做什么 | ✓ "需要正式合同和资金托管的大项目，它还不适合" |
| 同行细节 | 一句 prompt 原话、一个耗时、一个版本号 | ✓ "prompt 就一句：按项目归档邮件；从零到能用一个下午" |

宣发片常见的划走点：功能罗列超过 3 项却没有画面、背景交代超过 5 s、术语堆叠没有白话、结尾只剩"欢迎试用"没有具体动作。主张后紧跟证据句就是这个 profile 的衔接方式；留存曲线与自审清单见 [storytelling.md](storytelling.md)。

## 视觉语言

- 浅色纸底或深色单色底 + 一个强调色（`palette.accent`）；hairline 描边、软阴影、圆角面板；大留白。
- 真实录屏是主体：`Screen`/`DeviceFrame`（phone／laptop／browser）+ `Marker`/`Callout` 指出动作 + `UIZoom` 放大结果 + `MacCursorTrail`（真 macOS 光标，点击变手型；旧 `CursorTrail` 仍可用）/`TapRipple` 让操作可见；关键结果放慢或 `Clip hold` 定帧，答案出现前不切走。
- 对比用 `BeforeAfter`（同构图只变一个变量）；数据用 `MetricTile`；步骤用 `StepRail`；prompt→结果用 `PromptBubble` + `Terminal`。
- 运动：spring damping ≥ 180、位移 ≤ 80 px、缩放 ≤ 1.08、交叉淡入 0.4 s；**禁用**白闪、整屏震、RGB 分离、砸字、印章、hit-stop（`preset product` 下这些部件自动失效）。
- 划重点用 `Note`（细单笔手绘下划线 / 框，`kind: 'underline' | 'box'`），一屏一个；漏光、放射、拖影是爆款词汇，`preset product` 下自动不渲染。
- 每条片一个专属镜头：这个产品独有的画面（它解决的那件事的可视化），`film.shots[].bespoke` 写明。
- 生成素材只做概念解释并在角标标注"示意"；不冒充演示。
- 常驻角标：产品名 + 版本 + 作者。

## 音乐

默认有一条轻的节奏床（`gain 0.35`、`duck 0.5`），作者明确说不要才关。调性从产品卡推导（[music.md](music.md)）：开发者 / 效率工具 → 沉稳或科技冷感，消费类 → 动感，生活类 → 温暖；能量低的产品不配燃曲。`music.py plan` 出 2 条提示词、`rank` 打分、`fit` 只把一次抬升放在"我做了什么"那句上，`grid` 让录屏切换落在小节线。交付带 BGM 版 + 干声版。

## 封面与发布包

三比例生图候选：真实场景里的产品界面／设备（桌上的手机、屏幕前的手、真实的光），标题 4–14 字，不夸张不承诺画面外的东西。交付 3 个标题（问句／数字／"我做了个…"型）+ 首评（试用链接 + 一句边界）+ 话题包。

## 本 profile 的验收

- 录屏在前 10 秒内出现；每个能力主张有证据；写出"不适合谁"。
- 实测语速 6.9–7.9 字/秒；气口只出现在证据段；可见变化 ≤ 2.5 s。
- `qa.py`：零白闪、零震屏、无黑场；字幕不压住界面关键操作。
- 三画幅、封面、标题包、证据清单、qa.md 齐全。
